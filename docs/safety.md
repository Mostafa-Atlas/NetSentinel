# Scanning safety

Use NetSentinel only on a network you own or are authorized to administer. The administrator must enter and approve a private IPv4 CIDR before any probe runs. The baseline refuses public, loopback, multicast, and ranges larger than 256 addresses. Scans use TCP connect probes with a one-second timeout and bounded concurrency. No exploit, credential, stealth, or packet-capture functionality is included. Results are time-bounded observations, not vulnerability findings.

Manual discovery presents the CIDR, maximum address count, port count, and concurrency before queuing. The worker reads OS neighbor hints, tries ordinary ICMP ping if available, and makes TCP connect attempts to the scope's configured ports. A neighbor entry alone is not proof that a host is currently reachable. No response remains unconfirmed. Docker bridge networking, VLANs, VPNs, firewalls, and client isolation can hide devices or MAC information. The standard container uses bridge networking and does not request host network access or elevated capabilities.
