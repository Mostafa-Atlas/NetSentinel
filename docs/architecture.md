# Architecture

The browser uses the same origin for the API in production; Vite proxies API requests during development. FastAPI owns authenticated API routes, a bounded asynchronous scan worker, a single scheduler, and SQLite persistence. API handlers queue scan jobs and return promptly. UTC timestamps are rendered in the browser's local timezone. Observations remain immutable; current status is derived from recent evidence.

Run one process in the standard deployment. Multiple web workers would each start a scheduler, so horizontal scaling needs an external scheduler and job coordination that are outside Phase 1.

Device identity is deliberately conservative. Repeated observations with the same observed MAC can update one device across IP changes, but a new MAC on an old IP creates a separate device. Without a MAC, the app maintains a separate provisional IP identity. The dashboard shows this confidence rather than silently merging uncertain records. Address rows preserve first and last observation times.

The single scheduler checks enabled approved scopes every 30 seconds only when the owner has enabled automatic discovery. It enqueues at most one due run per scope and respects a minimum 15-minute interval. Existing queued/running jobs and a recent finished job prevent duplicate scheduling after restart. A device becomes offline only after the configured number of consecutive no-response observations; a single miss remains unconfirmed. The first service observation establishes a baseline, while a later transition to reachable is a change candidate.

The topology endpoint uses virtual subnet nodes. It infers a device-subnet edge when an observed address falls within an approved CIDR, records that provenance, and never asserts a physical link. The overview derives counts from current device summaries and timestamps them with the most recent scan or observation. Both views retain explicit empty and partial-data states.

P8 groups scopes under named profiles. The migration places existing scopes and devices in a Default profile. CIDR uniqueness is per profile, and reconciliation and inferred subnet links stay within a profile; two labs using the same private IP therefore retain separate inventories. New observations record the probed IP so an owner-confirmed split can move attributable evidence. Historical observations without an IP are retained but cannot be split automatically. Merge refuses conflicting observed MACs and cross-profile identities. Scopes with scan history cannot be moved between profiles because that would change the meaning of existing evidence.

P9 adds a short listener window only for scopes whose passive policy is explicitly enabled. It joins the standard mDNS and SSDP multicast groups, sends no discovery packets, bounds packet size and count, checks sender IP against the approved CIDR, and parses only mDNS A names and SSDP alive types. Hints attach to an already observed device; they never create one on their own. The listener can fail to bind or miss traffic under Docker bridge, VLAN isolation, or an occupied UDP port, in which case active discovery continues. The protocol references are [RFC 6762](https://www.rfc-editor.org/rfc/rfc6762) and the [UPnP Device Architecture](https://upnp.org/specs/arch/UPnP-arch-DeviceArchitecture-v2.0-20140901.pdf).

P10 evaluates per-device rules after all service observations for a scan are stored. One rule/check row is recorded per device, port, and scan. A reachable result takes precedence when the same device has multiple observed addresses. A rule alerts only after its configured consecutive misses and deduplicates the open alert; a responding check resolves it. Quiet hours and maintenance suppress new alerts but preserve check evidence. The rule uses the scope's existing bounded TCP probes, so its cadence follows manual or opt-in scheduled discovery rather than adding independent network traffic.

P11 host reports are optional and outbound-only. An owner enrollment binds a random, one-time credential to one device. The database stores a SHA-256 digest of the high-entropy token; the server compares it in constant time and supports expiration and revocation. Each report needs a timestamp and a nonce unique to its enrollment, stored transactionally with the report to reject exact replays. Remote reporting requires HTTPS as seen by the ASGI application, with loopback HTTP allowed for local development. The server does not trust a raw forwarded-protocol header from the client. Report payloads are bounded and never execute server-side commands. The standalone host script makes one outbound POST, refuses redirects, and includes Docker names/states only when explicitly requested. This follows [OWASP REST transport guidance](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html) and Python's [secrets module](https://docs.python.org/3/library/secrets.html).

P12 stores owner-supplied device pairs in a separate topology link table. A canonical ID order prevents duplicate pairs, and same-profile validation prevents relationships between overlapping private networks. These links have explicit owner provenance and are drawn differently from inferred IP-to-subnet links. Device comparison reads persisted evidence only and includes observation timestamps. Merge reassigns Phase 2 hints, rules, agent records, and nonconflicting topology links; duplicate check-rule ports block a merge. Splitting a device with device-scoped rules or agent records is refused because their address assignment would be ambiguous.
